# DECISIONS — работа №15

1. **Фабрика собирается из списка каналов, каждый канал сообщает свой `type()`; сервис получает фабрику через конструктор.**
   В фабрике нет `switch` и логики отправки. Подключение нового канала — регистрация экземпляра. Внедрение через конструктор позволяет проверить `NotificationService` с фиктивным каналом: в SelfCheck `RecordingChannel` фиксирует вызовы `send` без реальной отправки.

2. **Отказ канала — результат `NotificationResult.failed`, а не исключение; причину формулирует сам канал (`rejectionReason`).**
   Неподходящий адресат — штатная бизнес-ситуация. При массовой рассылке одна неверная запись не должна прерывать остальные. Исключения оставлены для ошибок конфигурации (канал не подключён, дубликат регистрации) и неверного типа канала на входе.
